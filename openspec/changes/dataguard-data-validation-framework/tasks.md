## 4. Check Types Layer

- [x] 4.1 Implement `run_row_count(config, source_df, target_df) -> CheckResult`: compute absolute and percentage delta; 0 vs 0 = PASS (0% delta); 0 vs N = FAIL (100% delta); status PASS when delta ≤ threshold, FAIL otherwise; no sample rows; verify with unit tests covering pass/fail boundary, zero-source, and zero-target cases
- [x] 4.2 Implement `run_duplicate_detection(config, source_df) -> tuple[CheckResult, pd.DataFrame | None]`: group by key columns, count groups with size > 1; PASS when zero duplicates, FAIL otherwise; return up to `sample_rows` duplicate rows; verify with unit tests for no-duplicate (PASS), duplicate (FAIL + samples), and fewer-than-N-duplicate-rows (samples capped at actual count) cases
- [x] 4.3 Implement `run_null_threshold(config, source_df) -> tuple[CheckResult, pd.DataFrame | None]`: compute null rate for the configured column (nulls / total rows); PASS when null_rate ≤ threshold, FAIL otherwise; return up to `sample_rows` rows where the column is null; Result Record includes `actual_value` (null rate) and `delta` (actual_rate − threshold); verify below-threshold (PASS), above-threshold (FAIL + samples), and all-null edge cases
- [x] 4.4 Implement `run_referential_integrity(config, source_df, target_df) -> tuple[CheckResult, pd.DataFrame | None]`: exclude NULL source values from the check (report `null_count` in Result Record separately); find source values not present in target reference column; PASS when zero orphans, FAIL otherwise; return up to `sample_rows` orphaned rows; verify clean (PASS), orphan (FAIL + samples), and NULL-source-values cases
- [x] 4.5 Implement `run_reconciliation(config, source_df, target_df) -> tuple[CheckResult, pd.DataFrame | None]`: compute sum/count/avg aggregate on configured columns (NULLs excluded per SQL semantics; `null_count` reported per side in Result Record); PASS when delta ≤ threshold, FAIL otherwise; no sample rows; `delta` field = percentage delta of aggregates; verify all three aggregate functions at pass/fail boundaries and NULL-column edge cases

## 5. Execution Engine

- [x] 5.1 Implement `CheckResult` dataclass with fields: `run_id` (UUID v4), `check_name`, `check_type`, `status`, `actual_value`, `expected_value`, `delta`, `null_count`, `source_connector_type`, `target_connector_type`, `timestamp` (ISO-8601), `reason`; verify all fields serialize to dict correctly for both DB and file writers
- [x] 5.2 Implement the execution engine loop: for each check, instantiate connectors, call `connect()` inside a try/except — a `ConnectorError` records the check as ERROR and continues to the next check; dispatch to the appropriate check-type function; collect `(CheckResult, sample_df | None)` pairs; verify with a mixed-outcome run (PASS, FAIL, ERROR) that all results are returned and no exception propagates out
- [x] 5.3 Implement SKIP handling: before executing a check, if `enabled: False` or the check name is in the CLI `--skip` list, set status SKIP with reason and skip all connector calls; `--skip` is repeatable (`--skip check-A --skip check-B`); an unrecognized `--skip` name prints a warning to stderr and is ignored (does not exit non-zero); verify that a check with `enabled: False` produces a SKIP record with no connector calls, and that an unknown `--skip` name prints a warning without failing the run
- [x] 5.4 Implement empty-config guard: a Config File with zero check blocks exits 0 and prints `"No checks defined — nothing to run"` to stdout; verify with an empty checks list
- [x] 5.5 Implement run summary: after all checks complete, print per-check status lines and a final count line (`PASS: N  FAIL: N  SKIP: N  ERROR: N`) plus the Results Store path to stdout; verify that a 4-check run prints exactly 4 status lines and one summary line regardless of outcome mix
- [x] 5.6 Implement exit code: exit 0 when all non-SKIP checks are PASS; exit 1 when any check is FAIL or ERROR; a run of all-SKIP checks exits 0; verify exit codes for all-pass, any-fail, any-error, and all-skip cases
